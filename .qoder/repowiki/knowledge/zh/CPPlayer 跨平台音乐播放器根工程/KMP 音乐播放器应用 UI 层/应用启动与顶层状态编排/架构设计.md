模块由三个文件构成应用层最顶层的协作关系：
- `App.kt` 是 Compose 根 `@Composable`，通过 `collectAsState` 订阅 `AppModel` 暴露的 `StateFlow`（主题/动态色/纯黑模式），并在首次组合时调用 `syncPlaybackQuality`、`refreshUserProfile`、`startHistoryRecorder` 完成初始化；随后用 Voyager 的 `Navigator` 根据 `MusicBackend.stateFlow` 决定起点为 `SetupScreen` 或 `MainScreen`，并通过 `LaunchedEffect(state)` 监听后端 Ready 切换自动 `replaceAll`。
- `AppModel.kt` 以单例 `object` 充当应用服务定位器，仅依赖 `cp.player.kmp.*`（`MusicBackend`、`PlaybackController`、`HealthMonitor`、`SettingsStorage`、`ProviderCookieStorage`），对外暴露 `backendState`、`activeProviderFlow`、`userProfileFlow`、`recentTracksFlow`、`playbackQualityFlow` 等 `StateFlow`，内部用 `MutableStateFlow` + `runCatching` 封装设置持久化、用户资料拉取、最近播放记录、Provider 导入/切换/删除等操作，并提供 `modelScope`（SupervisorJob + Default）统一协程生命周期。
- `LoginStatusParser.kt` 是纯函数工具，从不同 Provider 返回的 `login/status` JSON 中兼容提取 uid，被 `AppModel.refreshUserProfile` 复用。
依赖方向单向：UI → AppModel → kmp 后端；本模块不持有平台实现细节，全部逻辑位于 `commonMain`。
