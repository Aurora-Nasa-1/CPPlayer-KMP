## 2024-09-01 - Optimizing Rapid Recompositions in Desktop Compose
**Learning:** In Compose, rapidly changing state (like media playback progress triggering continuous recomposition) requires strict handling of both heavy object allocation and engine interaction. Instantiating objects like `Brush.radialGradient` on every recomposition cycle directly inside the render block causes noticeable GC overhead. Additionally, binding intense engine actions (like `onSeek` calls to the media player) directly to continuous input streams (like `Slider`'s `onValueChange`) leads to severe UI and playback stutter because the engine struggles to process the continuous flood of seek requests.
**Action:** 1) Always memoize expensive graphical objects (`Brush`, `Path`, etc.) using `remember` keyed to their invariant dependencies (like color themes). 2) For continuous input controls (like progress sliders) bound to media engines, always implement a local staging state (`seekValue`) for `onValueChange` and defer the actual engine action to `onValueChangeFinished`.
