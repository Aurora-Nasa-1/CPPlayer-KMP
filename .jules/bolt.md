## 2024-05-24 - Avoid O(N^2) lookups and fix duplicate queue entries
**Learning:** Using `indexOfFirst { it.mediaId == mediaId }` inside a loop iterating over map entries causes O(N^2) performance issues when processing large batches of queue updates. Moreover, `indexOfFirst` only ever returns the *first* occurrence of a `mediaId`. If a user adds the same track multiple times to the playback queue, subsequent instances will not have their summaries resolved, leaving them in an unplayable or un-displayable state.
**Action:** When updating queue entries from a batch resolution map, iterate over the queue indices directly (e.g. `for (idx in _queue.indices)`) and fetch the resolved data via O(1) map lookup (`val summary = map[entry.mediaId]`). This guarantees O(N) performance and ensures all duplicate entries in the queue are properly updated.
