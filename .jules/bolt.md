## 2024-05-18 - Jetpack Compose Recomposition Bottlenecks in Media Playback
**Learning:** In Compose UI, frequently changing states like media playback `positionMs` (which fires multiple times a second) cause rapid, continuous recompositions. Any objects created directly inside these composables—such as graphic elements like `Brush.radialGradient`, or string allocations via `formatTimeMs` or `"${variable}"`—will be continuously instantiated. This results in significant garbage collection (GC) pressure, leading to UI stutter and CPU overhead, particularly when combined with heavy rendering paths or user interactions like dragging a `Slider`.
**Action:** When working on components that consume fast-changing state in Compose, aggressively memoize heavy object creations and expensive operations using `remember`. For format strings dependent on high-frequency numbers (like milliseconds), memoize them based on a lower-frequency truncation (e.g., `remember(timeMs / 1000)`). Remove unnecessary string interpolation. When handling seek interactions in a Slider, use a local `remember`ed state to bypass continuous engine seek calls until `onValueChangeFinished` is fired.
