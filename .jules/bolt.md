## 2026-09-19 - Rapid Recomposition Overhead from Fast-Changing State
**Learning:** In Jetpack Compose screens that observe fast-changing state like `PlaybackUiState.positionMs` continuously, directly instantiating graphics objects (like `Brush`) or allocating formatted strings (like `formatTimeMs(positionMs)`) in the composition phase causes significant CPU overhead and garbage collection (GC) pressure due to thousands of allocations per minute.
**Action:** When working on media player controls or any components updating continuously, isolate fast-changing state to smaller, targeted components if possible. Alternatively, memoize string formatting by keying `remember` to a truncated version of the state (e.g. `remember(positionMs / 1000)`) and always wrap graphic allocations like `Brush` in a `remember` block tied to their underlying theme color dependencies.
