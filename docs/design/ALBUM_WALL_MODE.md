## 实施状态（2026-10-06 · 第二轮重写）

**P0 已落地**（编译 + 23 项单测 + 13 张离屏出图核对）。第二轮按用户反馈**重写了数据层与
交互层**：瓦片内容从「专辑 + 歌单」改为「**专辑 + 歌曲 + 本地**」，并修掉了第一批实现里的

### 数据源：四个，各司其职

| 源 | 取法 | 瓦片比例 | 上墙理由 |
|---|---|---|---|
| 收藏专辑 | `album/sublist` | `1:1` | 方形瓦片的主体，一屏能放很多张 |
| 我喜欢的音乐 | 「我喜欢的音乐」歌单的曲目 | `2:1` | **用户明确表达过偏好的歌曲**，优先级最高 |

| 本地歌曲 | `AppModel.localMedia` | `1:2` | 离线也完整，且是唯一"没有封面"的一类 |

> 在视觉上无从区分 —— 上墙只会是一堆长得一样的方块。这是第二轮重写的直接原因。

### 第二轮修掉的缺陷

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **点击穿透** —— 点 HUD 上的读数会打开它底下那张专辑的海报 | 浮层没有手势 ⇒ 事件穿透到画布 | `Modifier.consumeAllPointerInput()` + `WallOverlaySlot` 包住每个浮层；画布点击加 `posterId != null` 保险 |
| 2 | **海报里的按钮点不到** | 交互层是 `fillMaxSize` 且画在海报**之上** | 把 `WallPosterOverlay` 移到交互层**之后** |
| 3 | **点遮罩关不掉海报**（反而又开一张） | 遮罩无手势、事件落到画布 | 遮罩接管点击 = 关闭；卡片自身吞事件 |
| 4 | **右侧缩放谱显示错乱** —— 变成一根贯穿整屏的长条 | 轨道用了 `fillMaxHeight()` 的兄弟 `Box`，把 Surface 撑到父容器最大高度 | 轨道改用 `drawBehind` **画**，不参与测量 |
| 5 | **缩放谱标签被裁掉一半** | 写死 46dp 宽，而"马赛克"三个字就要 36dp | 宽度由内容撑开；窄屏收成纯圆点 |
| 6 | **滑块与层名对不上**（差 ~3%） | 行是等距的、层焦距不是，直接 `zoom = ratio` | 行圆心对齐到整数行号后再在相邻层焦距间插值（`zoomAtLadderRatio`） |
| 7 | **捏合缩放一次之后位置全乱** | `pointerInput(Unit)` 的 lambda **捕获了首次组合时的 layout** | 把"当前布局 + 布局输入"挂到 `WallState`，缩放统一走 `state.zoomTo(...)` —— 手势不再捕获任何随组合变化的值 |
| 8 | **表冠/缩放谱缩放时画面往左上漂** | 这两个入口直接改 `zoom`，不走锚定 | 同上：所有入口统一走 `zoomTo`（内含锚定） |
| 9 | **换排序/跨阈值时墙是"跳"不是"滑"** | FLIP 触发条件写成 `ps.size != layout.spans.size`（恒 false） | 改成逐项比较 `ps != layout.spans` |
| 10 | **"曲目数"排序按标题长度排** | 第一版的占位实现没替换 | 换成三个真实排序：最近 / 标题 / 类型 |
| 11 | **窄屏浮层互相压住** | 表冠与读数条都在底部 | 窄屏把表冠抬到读数条上方；读数条切 `compact` |
| 12 | **出图与真页面不一致**（预览给了假的通过） | 浮层堆叠在页面与夹具里**各写一份**，改了一边 | 抽成共享的 `WallChrome`，两边走同一份代码 |

### 第三轮：沉浸播放器 + 三个反馈问题

用户反馈：**播放不了**、**放最大太模糊**、**大卡片似乎是灰色的**、要求补完整沉浸播放器。

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 13 | **点了播放没反应** | 海报的播放键只对专辑 push 详情页，歌曲 / 本地直接什么都不做 | 接真播放（见下表）；拿不到可播曲目时**必须出声**（`UiEvents.notify`），静默失败会被当成界面坏了 |
| 14 | **大卡片是灰色的** | `resized()` 给**所有** URL 追加 `?param=WyH` —— 本地封面是 `file://` / `content://`，追加查询串把路径弄坏 ⇒ 加载失败 ⇒ 灰块 | `resized()` 只对 `http(s)` 生效。这是**共享工具函数**的缺陷，修一处全仓受益 |
| 15 | **放最大太模糊** | 取图尺寸按**焦距**分档，而实际渲染尺寸随窗口 / 沉浸层变化 —— 大窗口下 800 的图被拉到 1300+ | 改成按**目标渲染像素**分档（128/256/512/1024/1440），瓦片、海报、沉浸封面三处统一走 `wallCoverRequestSize` |
| 16 | **沉浸层里墙透上来** | 沉浸层只有半透明遮罩，底下的 300–680px 大瓦片会透上来和歌名叠字 | 加不透明底色；并把"播放器主体"与"队列"改成 `weight` 上下分栏（原先队列绝对定位在底部，矮窗口会和控件重叠） |
| 17 | **Z4 是"铺满的海报 + 播放器"两层** | 海报自己还有一段"铺满整屏"，和沉浸层重复 | 海报去掉铺满段，改为随沉浸层交叉淡出（0.88 → 1.0） |

**播放语义**（三种类型的队列不同，这是有意的）：

| 类型 | 队列 | 理由 |
|---|---|---|
| 歌曲 | 墙上所有歌曲，从点中的起 | 于是"队列 = 墙上的邻居"成立（§7.3） |
| 本地 | 墙上所有本地文件 | 同上，离线自洽 |
| 专辑 | 那一张专辑的曲目 | 点专辑的语义是"听这张专辑"，不是"从这首往下听全库" |

> ⚠️ 歌曲分支走 `AppModel.playTrackClicked` 而不是直接 `playQueue`：一起听进行中点歌的
> 语义是「下一首播放」，绕过它会让一起听不同步。
>
> ⚠️ 播放成功后才推进焦距到沉浸层。乐观推进的话，专辑为空 / 未登录时会进到一个
> 没有曲目的沉浸层（`WallImmersive` 直接 return），用户看到的是"一张巨大的网格"。

**沉浸层（`ui/wall/WallImmersive.kt`）**：不透明底 + 封面放大模糊背景 + 居中大封面
（从 `scale(0.88)` 长到 1，接住海报层）+ 歌名 / 歌手 + 可拖进度条 + 上一首 / 播放暂停 /
下一首 + 「接下来」队列环（墙上的邻居）。全部由 `zoom` 驱动，没有独立路由。

### 尚未落地（P1+）

- **Z4 完整沉浸播放器**：目前是"海报继续铺满"的几何版（队列环 / 表冠双语义 / 歌词未做），
  且需要先点开一张专辑才成立。

## 0. 一句话定义

**把整个音乐库铺成一堵可无级缩放的封面空间 —— 浏览、聚焦、播放不是三个页面，
而是同一个曲面上焦距不同的三个位置。**

用户拿到的不是"又一个专辑列表"，而是一个**可以拧焦距的物件**：
往一个方向拧，音乐库从一片色彩尘埃长成一面马赛克墙，再长成一张海报，
最后长成一个正在播放的唱片。整个过程没有一次跳转、没有一次白屏、没有一次页面压栈。

## 1. 为什么它是「模式」，而不是「一个页面」

这一节必须先立住，否则后面所有设计都会被当成"花哨的专辑列表页"，
最后被简化成 `LazyVerticalGrid` + 一个 zoom 滑块。

### 1.1 判据一：它改变的是**呈现方式**，不是呈现内容

同一份数据（`AlbumSummary` 列表），在墙里以**尺度空间**呈现；退出后仍是原来的
列表 / 栅格。数据层、网络层、缓存层**一行都不用改**。

> 技术后果：模式是**视图层的持久状态**，不是一条路由。
> 它不能是 `class AlbumWallScreen : Screen` 就完事 —— 那只是一个页面。

### 1.2 判据二：它**接管输入语法**

进入墙之后，同一个物理输入的语义被整体改写：

| 输入 | 浏览模式（现状） | 墙模式 |
|---|---|---|
| 滚轮 | 纵向滚动页面 | **改变焦距** |
| 拖动 | 选中 / 无 | **平移画布**（带惯性） |
| `Esc` | 弹回栈根 | **缩回上一档焦距**，到顶才退出模式 |
| 空格 | 无 | 播放 / 暂停 |

> 技术后果：模式状态必须**高于 Navigator**。滚轮语义的接管要走
> `HorizontalWheelScroll.kt` 已经验证过的 `expect fun Modifier.…` 路线
> （`desktopHorizontalWheelScroll` 是现成范式：桌面实现、Android 空实现）。
> `Esc` 的接管要接进 `Main.kt` 现有的
> `canGoBack = navigator.size>1 || DesktopShell.pageCanGoBack || DesktopBackDispatcher.hasHandlers`
> 链路 —— **墙模式下它是第四条判据**，且优先级最高。

### 1.3 判据三：转场是**缩放的延续**，不是一次压栈

- 从任何页面"放大进入"墙：进入动画就是一次 zoom-in；
- 从墙"放大进入"播放：不是 `navigator.push(PlayerScreen())`，而是 zoom 从 0.78 走到 1.0；
- 退出：反向缩放回进入前的焦距与位置（保存"相机状态"）。

> 技术后果：进入 / 退出必须能拿到**上一帧的相机状态**（焦距 + 平移 + 焦点），
> 这决定了模式状态里要存 `camera: {zoom, panX, panY, focusId}` 而不只是一个布尔。

### 1.4 判据四：它让**底部导航栏与标题栏溶解**

进入墙后，三 Tab（首页 / 搜索 / 我的）与页面标题栏随焦距淡出 —— 用户"不在任何一个
Tab 里"。这正是 `StandbySettingsScreen` 那类"全屏态"的做法，但墙是**可交互**的全屏态。

> 现存资产：`LocalWindowChromeActive`（窗口标题栏是否接管返回入口）已经是这类
> "外壳是否让位"的判据，墙模式可以直接复用它决定"要不要自绘返回入口"。

### 1.5 反面论证（先自己打一遍，免得评审时才被打）

| 质疑 | 回应 |
|---|---|
| "这不就是个相册式的网格 + 缩放吗？" | 相册缩放只改大小，不改**信息层级**；墙的每一档焦距是**不同的阅读单位**（色块 / 角标 / 标题 / 海报 / 播放器）。且队列被空间化了（§7.3），这是相册没有的。 |
| "无极缩放会不会很难用、找不到东西？" | 这正是 §3.1 软磁吸要解决的：连续但可落点，四档命名层带 tick 反馈。 |
| "桌面端鼠标滚轮本来就是滚页面，抢过来会不会很怪？" | 地图类应用（Google Maps / Figma / 相册）早已建立"滚轮 = 缩放"的肌肉记忆。且墙里**没有"页面"可滚** —— 内容高度就是画布高度，纵向滚动本来就没意义。 |
| "实现成本会不会失控？" | §10 拆成 P0–P4，P0 只是"连续 zoom + reflow + 鱼眼"，约等于一个自定义 `LazyLayout`，不碰任何现有页面。 |

### 1.6 推论：入口必须长在内容上

既然墙是"把现有内容展开出来"，那它的入口就**不能是导航栏里的第四个 Tab** ——
那会立刻把它降格成一个页面。入口必须**从已有内容里长出来**，且进入的动画本身就是
"这块内容展开成墙"。完整设计见 §6.5。

## 2. 尺度空间：五级命名层

墙的全部设计压在一个连续标量上：`zoom ∈ [0, 1]`。

| 层 | 名称 | 单位格边长 | 瓦片比例（同屏配比） | 呈现 | 阅读单位 |
|---|---|---|---|---|---|
| **Z0** | 尘埃 Dust | 15–24dp | 全部 `1:1` | **纯色块，不加载图片、不显示文字** | 库的规模与色彩分布（"看形状"） |
| **Z1** | 马赛克 Mosaic | 56–88dp | `1:1` 约 55% · `2:2` 约 12% · `2:1`/`1:2` 各约 15% | 封面 + 角标一行标题 | 快速扫视（参考图 1 的观感） |
| **Z2** | 封面 Cover | 130–200dp | `1:1` 约 42% · `2:2` 约 22% · `2:1`/`1:2` 各约 18% | 封面 + 标题 / 歌手（见 §4.5） | 舒适浏览（**默认层**） |

> ⚠️ 比例还受**列数**约束：`最大跨度 = 列数 / 2`。焦距拉大时列数会掉到 3–4，
> 此时再允许 2 格宽的瓦片，一行只放得下一张，整面墙会变成"几块巨大的方块"。
> 超出就降级（`2:2 → 1:2`、`2:1 → 1:1`），保住"高"这个特征。
| **Z3** | 海报 Poster | 300–430dp | 单张竖版大卡 | 大卡：封面 + 标题 / 歌手 / 播放键 + 模糊封面做底 | 决策（参考图 2 的观感） |
| **Z4** | 沉浸 Immersive | 满屏 | 1 | 封面铺满 + 浮层控件 + 边缘环绕其余封面 | 在听（**播放器本体**） |

> 「单位格」是墙的原子尺寸，瓦片占几个单位格就决定它的比例 —— 详见 §4.5。
> 配比不是随机：`2:2` 的配额随焦距从 0 连续涨到 30%，且**先给权重最高的那批**。

### 2.1 边长按**对数**增长，不是线性

```
tileSize(z) = 15 * 30^t        (t = 归一化到 [0,1] 的焦距)
```

线性插值会让 Z0→Z1 段"看不出在缩放"（15→64 只占全长的 1/6，却要走 6 倍变化），
Z2→Z3 段又"一秒冲过去"。对数映射与音高同构，每一档"手感上的步长"一致 ——
**这是"跟手"的数学来源，不是调参调出来的**。

实现上写成关键帧 + 段内 `smoothstep`（原型即如此），保证段间导数连续、无折角：

```kotlin
private val SizeKeyframes = listOf(
    0.00f to  15f,   // Z0 尘埃
    0.30f to  64f,   // Z1 马赛克
    0.55f to 150f,   // Z2 封面
    0.78f to 330f,   // Z3 海报
    1.00f to 330f,   // Z4 沉浸（网格交给沉浸层接管）
)
```

### 2.2 文字随焦距**交叉淡入淡出**，不是"到某层才出现"

- Z1 角标：`alpha = smoothstep(0.22, 0.34, z) * (1 - smoothstep(0.60, 0.72, z))`
- Z2 封面下标题：`alpha = smoothstep(0.42, 0.56, z) * (1 - smoothstep(0.70, 0.80, z))`

两段区间**刻意重叠**（0.42–0.72）：重叠区里角标与标题同时半透明，
视觉上是"角标从封面里浮出来、变成封面下的标题"。没有重叠就会出现
"字突然消失又突然出现"的硬切 —— 那正是"看起来像几个页面拼起来"的元凶。

> 圆角也要跟着走：`radius = clamp(tileSize * 0.14, 4, 26)`。
> 小瓦片用大圆角会显得像药丸，大瓦片用小圆角会显得像贴图。
> 这与 `ui/theme/Shape.kt` 的 8 槽刻度不冲突 —— 那是**组件**的刻度，
> 这里是**连续量**，只在贴近 Z2/Z3 时才吸到刻度值（`largeIncreased` / `extraLarge`）。

## 3. 无极调节的三条物理

"像 Apple Watch 一样无极调节"不是"能连续缩放"这么简单。表冠的手感由三件事共同构成。

### 3.1 软磁性刻度（连续 + 可发现）

纯连续缩放的致命问题是**没有落点**：用户永远停在某个"差一点"的构图上。
Apple Watch 的表冠有**触觉刻度**，纯分档又失去无极。

所以：`zoom` 连续，但在四个命名层处叠一个**弱弹簧**：

```kotlin
/** 软磁吸：靠近命名层时向层值收敛，收敛力随距离衰减，且在层上完全释放。 */
fun magnetic(z: Float, levels: FloatArray, radius: Float = 0.045f, strength: Float = 0.42f): Float {
    var out = z
    for (lv in levels) {
        val d = z - lv
        if (abs(d) < radius) out -= d * strength * (1f - abs(d) / radius)
    }
    return out.coerceIn(0f, 1f)
}
```

- `strength = 0.42` 意味着**最多拉回 42% 的偏移** —— 用户想停在两层中间，照样停得住；
- 每次**跨过**一个命名层边界时触发一次 `HapticFeedback`（Android）/ 视觉 tick（桌面），
  让"无极"有刻度感。

### 3.2 惯性 + 速度场

滚轮 / 滑动结束后，`zoom` 不应立刻停 —— 表冠有飞轮。用
`Animatable.animateDecay(velocity, exponentialDecay())`，与 pan 的惯性共用一套速度场。

> ⚠️ 动效令牌必须从 `CpMotion` 取（`ui/theme/Motion.kt`），
> **缩放属于 spatial，绝不能把回弹用到透明度上**。这是该文件 KDoc 里明写的坑。

### 3.3 焦点鱼眼（尺度空间在焦点处局部弯曲）

前两条只让"整面墙一起缩放"。真正的表冠手感来自第三条：
**焦点处的瓦片比周围大，且衰减是平滑核**。

```kotlin
val d2 = (center - focus).lengthSquared
val r  = tileSize * 2.05f
val mul = 1f + fishGain * exp(-d2 / (r * r))     // 高斯核，无硬边
```

- `fishGain` 随焦距变化：Z0 为 0（尘埃层做鱼眼会整片抖）、Z1–Z2 最大（0.17）、
  Z4 为 0（沉浸层不需要）；
- 用**高斯核**而不是线性 falloff：线性 falloff 在半径边界有一阶不连续，
  缩放时会看到一圈"涟漪"。

> 这条是本设计里**最"Apple Watch"的一点** —— 手表蜂窝网格的手感，
> 本质就是"焦点局部放大 + 平滑衰减"，而不是整体缩放。

## 4. 布局引擎：连续列数的「呼吸」reflow

### 4.1 列数是浮点，瓦片宽度连续

```kotlin
val colsF = (contentWidth + gap) / (tileSize + gap)   // 浮点
val cols  = floor(colsF).toInt().coerceAtLeast(2)     // 实际列数
val tileW = (contentWidth - (cols - 1) * gap) / cols  // 瓦片实际宽度
```

关键：**瓦片宽度由 `tileW` 决定，而不是由 `tileSize` 决定**。
于是 `tileSize` 连续增长时，`tileW` 连续增长；当 `colsF` 跨过整数，
多出一列，所有瓦片宽度按新列数重算 —— 这是一个**离散事件**。

处理方式：给它一个 ~180ms 的 spatial spring 把旧布局插值到新布局。
观感是整面墙"呼一口气"（每行重新分配），而不是硬切。这就是
**reflow 的"呼吸感"**，也是"连续缩放"在网格里唯一可行的实现。

### 4.2 缩放必须锚定，否则视野会跳走

缩放时如果 `pan` 不变，焦点下的内容会往屏幕外跑。必须做**锚定**：

1. 取焦点（指针位置，触摸端取视口中心）下最近的瓦片 `idx`；
2. 记下它在瓦片内的**归一化偏移** `off = (focus - slot(idx).topLeft) / slotSize`；
3. 改 zoom、重算布局；
4. 反解 `pan`，让 `idx` 的同一个归一化位置仍落在同一个屏幕点上：

```kotlin
panX = focusX - slotAfter(idx).x - offX * slotAfter(idx).size
panY = focusY - slotAfter(idx).y - offY * slotAfter(idx).size
```

> 这也是 Z3 海报"从墙里长出来"的机制（§7.1）：点瓦片时把锚点设在该瓦片中心，
> 缩放到 0.78 时瓦片中心**原地不动**，海报就从那里展开。

### 4.3 渲染：`LazyLayout` + 视口裁切 + Z0 不加载图片

- 用 Compose 的 `LazyLayout` 自定义布局，只组合视口 + 预取窗口内的瓦片；
- 156 张瓦片在 Z1 会同时可见 ~100 张 —— 全部走 `AsyncImage` 会立刻打满
  Coil 的请求队列。所以**按焦距分级取图**：

| 焦距层 | `coverUrl.resized(n)` | 理由 |
|---|---|---|
| Z0 | **不加载**，用 `CoverSeedCache` 里的主色画色块 | 一次取色永久复用，400 块也不卡 |
| Z1 | 160 | 同屏 100 张，160px 足够 |
| Z2 | 400 | |
| Z3 / Z4 | 900 | |

> Z0 是**零图片请求**的一层：它只依赖 `ui/theme/CoverColor.kt` 已有的
> `extractSeedColor` + `CoverSeedCache`。代价是要为墙新增一条**串行取色协程**：
> `CoverSeedCache` 的 KDoc 明写"**无锁，靠调用方串行**，不要从别处调用它"。
> 墙的取色量远大于播放器，必须二选一 —— 要么把缓存加锁，要么让墙复用
> `AppModel` 那条既有取色协程。**这是实现时第一个要定的技术决策**，不能含糊过去。

### 4.4 缩放 / 平移不触发重新测量

### 4.5 变比例瓦片：单元网格 + 天际线装箱

只做等尺寸瓦片，墙就只是个网格。要让它成为**马赛克**，瓦片必须同时存在
`1:1` / `2:1` / `1:2` / `2:2` 四种比例。

做法是把墙看作一张**单位网格**：单位格边长就是 §4.1 的 `tileW`（连续变化），
每个瓦片占 `(w, h)` 个单位格 —— 比例天然就是 `w:h`。

装箱用**天际线（skyline）底左算法**：

```kotlin
// sky[x] = 第 x 列当前的"地面高度"
// 给 (w,h) 找一个 x，使 max(sky[x..x+w-1]) 最小（最低、最靠左）
var bestX = 0; var bestY = Int.MAX_VALUE
for (x in 0..cols - w) {
    val y = (x until x + w).maxOf { sky[it] }
    if (y < bestY) { bestY = y; bestX = x }
}
for (k in bestX until bestX + w) sky[k] = bestY + h
```

复杂度 `O(n · cols)`：n=156、cols≈20 时约 3000 次比较，**每次缩放都重算也毫无压力**。

#### 为什么必须重算 —— 比例是焦距的函数

比例不是固定分配，而是**随焦距长出来的**：

```kotlin
fun spanOf(album: AlbumSummary, zoom: Float, rank: Int): IntSize = when {
    zoom < 0.10f -> IntSize(1, 1)                                   // Z0 尘埃：全部归一
    rank < (N * 0.30f * smoothstep(0.10f, 0.60f, zoom)).toInt() -> IntSize(2, 2)
    else -> baseSpan(album)                                         // 按内容类型
}
// 内容类型 → 基础比例：专辑 1:1 / 歌单 2:1 / 单曲与艺人 1:2
```

- **Z0**：全部 `1:1`，墙退化成一片均匀的色彩尘埃（只有色块，看不出结构）；
- 焦距上升，`2:2` 的配额从 0 连续涨到 30%，**权重最高的那批先长出来**；
- 同时内容类型开始分化：歌单 → `2:1` 横条，单曲 / 艺人 → `1:2` 竖条，专辑 → `1:1`。

> ⚠️ **配额必须是"稳定排名 + 单调阈值"**，不能是"每帧随机"，也不能"接近阈值就翻转"。
> 前者让墙一直抖，后者让某张专辑在阈值附近来回变形。
> 用 `RANK`（按权重排好的名次）去比 `rank < quota(zoom)`，每张专辑在一次缩放行程里
> **只会升级一次、不会回退** —— 这才是"呼吸"而不是"抽搐"。

#### 重排用 FLIP，而不是让它跳

列数变化或比例分配变化时，装箱结果整体改变，直接应用就是"啪"地跳一下。
所以每次重排时**用同一个单位宽分别装箱新旧两套比例**，两者之差就是纯粹的
重排位移（不含缩放），把它作为一次性偏移量做衰减动画：

```kotlin
val before = pack(prevSpans, prevCols)   // 注意：用**当前**的 tileW
val after  = pack(newSpans,  newCols)
tile.flip = before[i] - after[i]         // 之后约 550ms 内衰减到 0
```

> 观感上，缩放跨过阈值时整面墙会**洗一次牌**再落定。这就是"呼吸"。

#### 非方形瓦片的信息层级

**比例不是装饰 —— 多出来的那一格用来放信息：**

| 比例 | 内容 | 语义 |
|---|---|---|
| `1:1` | 只有封面（Z1 叠一行角标） | 一张**专辑** —— 一个单位格正好是一张封面 |
| `2:1` | 左方封面 + 右侧歌名 / 歌手 | 一首**歌曲** —— 歌曲本来就是"一行"信息，横条最省地方 |
| `1:2` | 上方封面 + 下方两行标题 | **本地文件** —— 普遍没有封面、名字很长，竖条才放得下 |
| `2:2` | 封面铺满 + 底部渐变上的标题 / 歌手 + 播放键 | 最值得点进去的那张（一张"卡"） |

> 这样"大瓦片"才不是"更大的图"，而是**能放下更多信息、因此值得点进去的那张**。
> 比例同时承担了两个职责：视觉节奏（马赛克），以及信息层级（谁能露出更多字）。

## 5. 排序即构图

墙的排序决定"墙长什么样"。所以排序在墙模式里**不是设置项，是构图手段** ——
它是工具栏上的一排 chip（`CpToggleChip` 现成），点一下整面墙重新构图。

| 排序 | 依据 | 观感 |
|---|---|---|
| 最近 | 各源内按时间倒序，再四源轮转交错 | 默认；新东西在左上 |
| 标题 | `title` | 找具体一首歌时用 |
| 类型 | `kind` 分组（专辑 → 歌曲 → 本地），组内按标题 | 同一类聚成色块，墙自然分区 |
| **色彩**（待做） | `extractSeedColor` 的主色色相 | **整面墙变成一条彩虹** —— 性价比最高的一条 |

> ⚠️ **权重与排序解耦**：`weight` 只由"最近"（四源轮转交错的名次）决定，与当前排序无关。
> 于是换排序是一次纯粹的洗牌 —— 谁长成 `2:2` 不变，变的是它们排在哪。
> 否则用户切一下排序会觉得"东西全变了"。
>
> ⚠️ **交错是必要的**：如果按源顺序拼接，前 30% 会全部落在同一个源上，
> 大瓦片会变成"清一色的喜欢歌曲"，马赛克的比例多样性就没了。

### 5.1 换排序 = FLIP 位移动画

排序切换时，每个瓦片从**旧槽位** spring 到**新槽位**，而不是瞬间重排。
实现即 §4.2 的锚定机制的反用：记下旧 `slot`，改顺序后算出新 `slot`，
把差值作为一次性偏移量做衰减动画。

> 观感上是"墙在洗牌"，而不是"页面重新加载"。这是"墙是有生命的"最直接的证据。
> **色彩排序是本设计里性价比最高的一条**：它只依赖已有的 `extractSeedColor`，
> 却能让用户第一次产生"这个东西有点意思"的反应。

## 6. 交互语法

### 6.1 共同语法（两端一致）

| 动作 | 结果 |
|---|---|
| 点瓦片（Z0–Z2） | 进入 Z3 海报（锚定该瓦片，原地展开） |
| 点海报的播放键 | 进入 Z4 沉浸 + 开始播放 |
| 缩回（滚轮向下 / 双指合拢 / `Esc`） | 逐档退回 Z0，到顶才退出模式 |
| 焦点悬停（Z1–Z2） | 鱼眼放大 + 标题浮出 |

### 6.2 桌面端（指针 + 键盘）

| 输入 | 行为 |
|---|---|
| 滚轮 | 无极缩放，焦点 = 指针位置 |
| `Shift` + 滚轮 / 中键拖 | 平移画布 |
| 左键拖空白 | 平移（带惯性） |
| 左键点瓦片 | 进 Z3 海报 |
| 双击瓦片 | 直接播放 + 进 Z4 |
| `[` / `]` | 按命名层步进 |
| `空格` | 播放 / 暂停 |
| `Esc` | 缩回上一档；到 Z0 时退出模式 |
| 右键瓦片 | `CpContextMenu`（播放 / 加入队列 / 收藏 / 下载 / 查看专辑 / 更多） |

两个**显式**的无极入口（给"不知道该滚轮"的用户）：

1. **表冠旋钮** `WallCrown` —— 角落一枚可拖拽圆盘，视觉上就是 Apple Watch 表冠。
   拖动 = 缩放，双击 = 回到默认层。它是模式的**签名控件**。
2. **缩放谱** `ZoomLadder` —— 右缘竖向轨道 + 四个刻度标签（马赛克 / 封面 / 海报 / 沉浸），
   连续填充，可拖动跳层。它是模式的**可发现性**：一眼看见"这里有四档"。

### 6.3 移动端（触摸）

| 手势 | 行为 |
|---|---|
| 双指捏合 | 无极缩放（锚定捏合中点） |
| 单指拖 | 平移 |
| 双击 | 在"当前层 ↔ 上一层"之间往返（相册双击缩放的肌肉记忆） |
| 长按瓦片 | 进入焦点（瓦片抬起 + 触觉），松手取消 |
| 右缘竖拖 | 表冠滑块（单手可达的缩放入口） |
| 下拉（Z0 时） | 退出模式 |

触觉：**每个命名层边界一次 `HapticFeedback`**，让"无极"有刻度感（§3.1）。

### 6.4 双栏（桌面宽屏）下的墙

墙在 `CpTwoPane` 的详情槽里时（`LocalEmbeddedInPane == true`），
- 不自绘标题栏与返回入口（返回在左栏选中态里）；
- 缩放谱与表冠**贴右栏内边缘**，不贴窗口边缘；
- `LocalIsExpanded` **不能**用来判"我是不是右栏"（AGENTS §6 明写的坑）。

### 6.5 入口与退出

**入口不能是第四个 Tab。** 那会立刻把墙降格成一个页面（§1.1）。而且底栏现在也不空 ——
`MainScreen` 的底部已经被 `MiniPlayer` + `NavigationBar` 占满，硬塞一个中央 FAB
会和 MiniPlayer 直接打架。所以入口设计成**三个成本不同的入口，全部长在现有内容上**：

| | 入口 | 位置 | 成本 |
|---|---|---|---|
| **01** | **手势** | 在任意专辑区域**双指捏合**（桌面端 `Ctrl` + 滚轮缩小） | 零成本（推荐） |
| **02** | **常驻** | 移动端顶栏「墙」图标；桌面端在窗口标题栏同排（与返回 / 账号 / 搜索并列） | 一次点击 |
| **03** | **情境** | 曲库 → 专辑 / 歌手页 / 搜索结果里的「用墙看」 | 带上过滤条件 |

三条各自解决不同的问题：

- **01 手势**是唯一能表达"这是模式"的入口。iOS 主屏捏合进 App 资源库、
  Apple Watch 转表冠 —— 同一套肌肉记忆：**"把眼前的东西收拢 / 展开"**。
  它还有一个额外好处：**进入点即锚点**。在曲库的专辑栅格里捏合，那一块的位置
  就是墙的初始焦点，动画连续（栅格瓦片"散开"成墙，而不是切一页）。
  这是 `CoverFlight` 共享元素思路的升级：不是一张封面飞，是**整块内容连续变成墙**。

- **02 常驻**解决"用户不知道有手势"。桌面端尤其重要 —— 指针用户不会去捏合。
  标题栏已经有一排动作（返回 / 账号 / 搜索），「墙」与它们同级是自然的。
  移动端放顶栏而不是底栏，正是因为底栏被 MiniPlayer 占了。

- **03 情境**是墙比列表强的地方。从歌手页进墙 → 墙上只有这位歌手的专辑；
  从搜索结果进墙 → 墙上只有命中项。**列表只能按顺序读，墙能一眼看形状。**

#### 退出必须与入口对称

| 入口 | 对应退出 |
|---|---|
| 手势捏合进入 | 缩回 Z0 → 回到原页面 |
| 顶栏图标进入 | 顶栏返回 / `Esc` |
| 情境进入 | 返回后回到那个歌手页 / 搜索结果 |

并且**记住相机状态**（焦距 + 平移 + 焦点项）：退出后再进入，落回上次的位置，
而不是重置到 Z2 的左上角。这就是 §1.3 "转场是缩放的延续"的反向应用 ——
进出都走同一条连续路径，中间没有一次压栈、没有一次白屏。

> ⚠️ 实现约束：`Esc` 要作为 `Main.kt` 的 `canGoBack` 判据之一加在**最前**，
> 但**不能改动原有三条**（`navigator.size>1` / `DesktopShell.pageCanGoBack` /
> `DesktopBackDispatcher.hasHandlers`）。漏改任何一条的后果，见本机 MEMORY 里
> 「播放页展开时没有返回键，Esc 却能退」那条。
>
> ⚠️ 手势接管用 `expect fun Modifier.desktopPinchToWall()`（桌面实现 `Ctrl`+滚轮，
> Android 实现捏合），照抄 `ui/component/HorizontalWheelScroll.kt` 的既有范式，
> **挂在专辑区域的容器上，不外溢到整页**。

## 7. 播放器：墙的最内层

"做一个符合这种设计的播放器"的答案不是"把播放页改好看点"，而是：

> **播放器 = 墙在 Z4 的状态。**

### 7.1 Z3 海报不是弹窗，是墙的一个焦距

参考图 2 里的"音乐海报"是一个居中弹窗 + 遮罩。本设计**不这么做** ——
弹窗意味着"墙被盖住了"，而墙模式的核心主张是"从来没有离开过墙"。

做法：海报的矩形**从焦点瓦片的屏幕矩形连续插值到目标海报矩形**（§4.2 的锚定）：

```
zoom 0.70 ────────────────► 0.88
      tileRect ──lerp──► posterRect
```

- 瓦片自身在 `posterAmt` 上升时淡出（避免"两层封面"）；
- 遮罩 `#dim` 的透明度也由 `posterAmt` 驱动，不是突然盖上；
- 缩放回 0.62 以下，海报自然消失，`S.poster` 清空。

> 结果：**海报是"墙在某个焦距上的样子"，而不是"盖在墙上的另一层 UI"**。
> 这与 `CoverFlight.kt` 已有的"共享元素飞行"是同一种思路，但更强：
> 飞行是两点之间的动画，这里整条路径都是可控的连续量。

### 7.2 Z4 沉浸层

- **背景**：当前专辑封面放大到 `inset:-14%`，`blur(58px) saturate(1.5) brightness(.5)`，
  再叠一层径向 veil。观感是"整间屋子都染上了这张专辑的颜色"。
- **封面**：`min(38vh, 320dp)` 方形，随 `immAmt` 从 `scale(0.84)` 长到 1.0 ——
  **不是淡入，是长出来**，接住 Z3 海报的位置。
- **控件**：底部一条浮起胶囊（`CpFloatingToolbar` 的形态）：
  上一首 / 播放暂停（`CpPlayPauseButton`）/ 下一首 + 一条细进度线（`CpSeekBar` 的极简变体）。
  **默认只露这条胶囊**，音量 / 队列 / 歌词 / 更多按需展开。
- **进度条可拖**，拖动时进度线变粗、显示时间码（复用 `ui/theme/Type.kt` 的
  `CpTypography.timecode`，等宽数字避免跳动）。

### 7.3 队列 = 墙上的邻居（本设计最有创造力的一点）

播放专辑 A 时，**队列顺序沿墙向外辐射**：下一首在右，再下一首更远。
沉浸层底部露出一排"接下来"的小封面（原型里是 8 个带序号的方块）。

缩小一点点（Z3.5）就能看到"接下来会听到什么" ——
**队列被空间化成了墙上的邻居，而不是一个弹出的列表。**

这条把"墙"和"播放器"真正焊成了一件事：墙不是背景，**墙就是队列**。
（对应到数据：`PlaybackController` 的队列顺序直接决定墙的 `order`，
当前曲目的索引决定沉浸层的中心。）

### 7.4 表冠的**双重语义**

同一个旋钮，在不同的深度做不同的事 —— 这是"一致性"而不是"复用"：

| 状态 | 表冠 = |
|---|---|
| Z0–Z3（浏览） | 焦距 |
| Z4（播放） | 进度微调（拖动即 seek）/ 音量（长按切换） |

> 用户只需要学一次"这个旋钮是改变当前状态的程度"。
> 这条也是为什么表冠值得作为一个**签名控件**长期存在，而不是一个临时缩放按钮。

### 7.5 歌词

两条备选，实现时二选一（倾向 B）：

- **A 横向 peel**：从右缘拉出歌词流，封面退为模糊背景；
- **B 竖向生长**（倾向）：竖向滚动时封面**连续缩小成唱片**，歌词从下方升起。
  与整堵墙的"缩放"语言同构 —— 歌词不是"另一个页面"，是"再放大一层"。

## 8. 与「待机 / 环境显示」合流

现存资产：`StandbySettingsScreen` + `AppModel.aggressiveStandbyFlow` +
`isAggressiveStandbyActive()`。

墙模式空闲 N 秒（默认 45s，可配）后进入**环境漂移**：

- 自动缓慢平移（Ken Burns，速度约 4dp/s）；
- 每 30s 缓慢换一次焦点（用 spatialSlow，不是切页）；
- 在 Z0 / Z1 之间极慢地"呼吸"（周期 ~90s）。

> 结果是**桌面端的一面活的墙**：闲置时它是壁纸，有人靠近（鼠标移动）立刻恢复可交互。
> 这是几乎零成本、感知极强的延展 —— 而它之所以能成立，
> 恰恰是因为"墙"本来就是一个**连续的、可停留的曲面**，而不是一页静态列表。

### 9.2 需要新增的接口（**必须遵守 AGENTS §5**）

```kotlin
// core/.../music/MusicSource.kt
// ⚠️ BackendResult.Unsupported 需要 message（见 BackendState.kt:89），不是无参构造。
suspend fun getUserAlbums(limit: Int = 100, offset: Int = 0): MusicResult<List<AlbumSummary>> =
    MusicResult.Unsupported("当前音源不支持专辑列表")   // ← 必须带默认实现

suspend fun getNewAlbums(area: String? = null, limit: Int = 50): MusicResult<List<AlbumSummary>> =
    MusicResult.Unsupported("当前音源不支持新碟列表")
```

> ⚠️ **给 `core` 的接口加成员必须带默认实现**（AGENTS §5），否则所有 Provider 一起编译不过。
> 且默认实现**绝不能**写成 `get() = MutableSharedFlow()` 这类"每次读属性都新建对象"的写法 ——
> 这里返回的是值类型的 `MusicResult`，天然没有这个坑；但**墙的"相机状态"若做成接口成员就要小心**
> （见 §9.3，那里刻意做成了 `StateFlow` 字段而非 `get()` 属性）。

### 9.3 模式状态的存放

```kotlin
// app/.../ui/wall/WallMode.kt
data class WallCamera(val zoom: Float, val panX: Float, val panY: Float, val focusId: Long?)

/** 墙模式是否激活。放在 AppModel 同级（高于 Navigator），因为要接管底栏与返回键。 */
val wallMode: StateFlow<Boolean>

/** 相机状态：退出后可还原。不进持久化（除非用户开了"记住焦距"）。 */
val wallCamera: StateFlow<WallCamera>
```

> 位置选择理由：进入墙时**三 Tab 底栏与标题栏要一起溶解**，
> 而它们住在 `MainScreen` 里、与路由页是**兄弟节点**（`UiFoundation.kt` 的
> `ProvideIsExpanded` KDoc 里详细写过这个结构坑）。所以模式状态必须挂在
> **根 Navigator 之上**，与 `ProvideIsExpanded` 同级，不能塞进墙自己的 ScreenModel。

### 9.4 取色（唯一的性能风险点）

`ui/theme/CoverColor.kt` 的 `CoverSeedCache` KDoc 明写：

> **无锁，靠调用方串行**：只在 AppModel 的取色协程（单条 `collect`）里访问 ——
> 一条协程不会与自己并发，因此不需要额外同步。**不要从别处调用它。**

墙在 Z0 需要对**整个库**取色（可能 300+ 张），量级远超播放器的"当前一首"。
**必须在 P0 就定下来**，二选一：

| 方案 | 代价 | 评价 |
|---|---|---|
| A. 把 `CoverSeedCache` 改成加锁（`Mutex` 或 `synchronized`） | 改动核心文件，需回归播放器取色路径 | 干净，但动的是被 KDoc 明确保护的资产 |
| B. 墙自己开一条串行取色协程，独立缓存 | 多一份缓存（约 16 → 512 条） | **推荐**：不动现有资产，且墙的缓存策略本就该不同（LRU 容量更大、可落盘） |

取色本身必须在 `Dispatchers.Default` 上（KDoc 明写**绝不能跑在 `backendScope`**），
且要**分批 + 可取消**（用户一拧焦距就取消上一批）。

## 11. 性能、无障碍与风险

### 11.1 性能

| 风险 | 对策 |
|---|---|
| 同屏 100+ 瓦片重组 | `LazyLayout` + 视口裁切；缩放/平移走 `graphicsLayer`，不触发 measure |
| 100+ 张图同时请求 | 按焦距分级 `resized()`（§4.3）；Z0 完全不加载图片 |
| 每帧 O(N) 找锚点 | N=156 时无感；上到 2000+ 张时改成**空间索引**（按行列直接反算下标，O(1)） |
| 取色阻塞 | `Dispatchers.Default` + 分批 + 可取消（§9.4） |
| 排序切换时的抖动 | FLIP 位移只动 `graphicsLayer`，不重排文本 |

### 11.2 无障碍（**连续缩放对无障碍是天然不友好的**，必须正面处理）

1. **"固定层"开关**：把 zoom 吸附成 4 档离散值，供需要确定性导航的用户；
2. `ZoomLadder` 实现为标准可聚焦滑块（`progressBarRangeInfo` + `setProgress` 语义动作），
   键盘上下键即可跳层；
3. 每个瓦片有 `contentDescription = "专辑：{name}，{artist}，{year}"`；
4. 触觉 tick **必须有等价的视觉反馈**（层标签闪一下），否则听障 / 无触觉设备用户拿不到刻度感；
5. 尊重系统"减少动效"：`CpMotion` 已依赖 `MaterialExpressiveTheme`，
   惯性 / 漂移 / 鱼眼在 reduced-motion 下自动退化为直接跳变。

### 11.3 已知风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 滚轮语义接管与其他页面冲突 | 只有墙模式接管；退出即还原 | 接管做成 `expect/actual` 修饰符，挂在墙的根容器上，不外溢 |
| `Esc` 链路改错会连带影响播放页 | `Main.kt` 的 `canGoBack` 是三条判据的或 | 墙模式作为**第四条**加在最前，不改原有三条；加回归测试 |
| 尘埃层主色质量参差 | 灰阶封面 `extractSeedColor` 返回 null | 回退到 `surfaceVariant`；这是 KDoc 里已有的既定行为 |
| 156 张够用，2000 张（本地大库）会退化 | 锚点搜索、取色、排序都是 O(N) | P3 后加空间索引与分页装载 |
| 用户找不到"怎么退出" | 全屏 + 底栏溶解 | Z0 处 `Esc`/下拉的 toast 提示；表冠常驻；顶栏在 Z0–Z1 不溶解 |

## 12. 附录：原型怎么玩

打开 [`album-wall-prototype.html`](album-wall-prototype.html)（156 张程序化生成的封面，零外部资源）：

打开后先是**入口面板**（§6.5 的三个入口），点任意一处「展开成墙」进入。

| 操作 | 效果 |
|---|---|
| 入口面板 | 三个入口的说明 + 「进入墙模式」 |
| 滚轮 / 双指捏合 | 无极缩放（焦点跟随指针） |
| 拖动空白 | 平移（带惯性） |
| 点一张瓦片 | 进 Z3 海报（从瓦片位置连续展开） |
| 点海报"播放" | 进 Z4 沉浸播放器 + 队列环 |
| 右下角圆盘 | **表冠**：上下拖动 = 缩放，双击 = 回默认层 |
| 右缘轨道 | **缩放谱**：点击 / 拖动跳层 |
| 顶部 chips | 换排序（**试试点"色彩"** —— 整面墙洗成彩虹） |
| `[` `]` | 按命名层步进 |
| `空格` | 播放 / 暂停 |
| `Esc` | 逐档缩回；到 Z0 时回到入口面板 |
| 右上角"浅色" | 切浅色主题（验证两套色板） |

原型里可以直接观察到的四件事：

1. **底栏与标题栏随焦距溶解**（z > 0.58 开始）—— "模式"的观感来源；
2. **HUD 实时显示 `z / 瓦片 px / 列数`** —— 列数在缩放中会"跳"，同时瓦片宽度连续变化，
   这就是 §4.1 的"呼吸 reflow"；
3. **海报与沉浸层都是从瓦片位置长出来的**，不是弹窗 —— §7.1 的主张；
4. **放大时大瓦片会自己长出来**：Z0 是均匀的色块尘埃，焦距上升后
   `2:2` 先长、然后歌单变成 `2:1` 横条、单曲变成 `1:2` 竖条 ——
   HUD 里的「大 / 横 / 竖 / 标准」读数会实时变化，且跨过阈值时整面墙会**洗一次牌**（§4.5）。
